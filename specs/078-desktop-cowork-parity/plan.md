# Implementation Plan: Desktop Cowork Parity

**Branch**: `main` | **Date**: 2026-07-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/078-desktop-cowork-parity/spec.md`

## Summary

Upgrade the unit-019 Electron demo into a first-class local cowork application without opening a local HTTP service or introducing a second runtime/policy model. Electron main exclusively owns a bundled Python sidecar and a bounded, versioned JSON-RPC-over-stdio V1 protocol; renderer access is restricted to an operation-specific typed preload facade. The sidecar integrates runtime and portable storage through `LoopPlaneHost` public facades, reuses existing normalized event serialization, and gains additive default-preserving resumed-interaction, checkpoint-derived audit, consistent portable-snapshot export, and read-only staged-validation seams.

A fixed opaque principal, portable Desktop Projects, and device-private workspace bindings define one local Desktop profile; an OS-backed exclusive Profile Ownership Lock acquired before recovery permits exactly one owning sidecar process for each canonical profile root, and an inner Desktop Interaction Lease permits one interactive run across panes/windows/processes. Session star state remains Host-owned, and unsent drafts remain renderer-transient. Web and Desktop reuse a transport-neutral first-party presentation package through separate adapters. Existing SQLite checkpoints and provenance-eligible Gateway artifacts provide Desktop durability through Host-owned snapshots; a pristine profile begins with explicit `absent_uninitialized` checkpoint/artifact states, so pre-Host bootstrap validates absence without opening or creating either store and the existing Host/store owners perform first normal initialization. Generation publication uses platform-scoped guarantees: exercised POSIX file/directory/both-parent `fsync` for physical-power-loss durability, and documented Windows regular-file flush/supported-local-volume write-through move/reopen for process/application-crash consistency without claiming parent-directory physical-power-loss persistence. A canonical immutable publication receipt binds pointer/proof/journals while active generation contents remain mutable; startup validates current schema/SQLite/artifacts. Fresh bootstrap is proof-before-pointer/Host; one all-writer Profile Mutation Lease excludes session/interaction/Project/workspace/capability/profile/backup mutations throughout backup snapshot/finalization and restore reservation/commit, while restore uses dual-slot full-preimage COW journals, startup-only adjudication after ambiguous proof acknowledgement, relink-before-binding-lookup, and deterministic rollback/fail-lock. Clean install/package proof uses one sole npm workspace/root lock, a complete Windows/Python-3.12 transitive hash lock rooted at build-only PyInstaller 6.21.0, a sole cleared-venv build wrapper with repeated Stage-B plus Stage-C delivery verification and PATH/global-PyInstaller denial, a required fully triggered Windows x64 package job, and one exact isolated-smoke CLI that copies the artifact outside the checkout. Stage B uses distinct bootstrap/final submitted GitHub PR reviews and Stage C adds a third delivery review over actual implementation before package execution; each has API-visible `APPROVED` state, API-controlled review ID/node ID, non-null `submitted_at`, exact reviewed `commit_id`, `user.type=User`, OWNER/MEMBER/COLLABORATOR `author_association`, immutable expected-approver equality, and inequality from the singular PR author. The verifier uses immutable shared repository/PR/expected-approver inputs plus the complete mode-required T002/T005/T090 review-ID/commit locator chain, one explicit short-lived token environment seam confined to an isolated verifier step, minimum read permissions, singular version-pinned PR/review/commit/tree/blob resources, complete non-truncated reads, and fail-closed redacted diagnostics. Final and delivery modes independently refetch prior reviews, enforce the exact T002-to-T005 full-tree allowlist, and never trust ADR/evidence as authority. Each content-addressed commit—not editable review-body/comment text or ambient auth state—determines its reviewed tree, canonical review-bundle digest, and accepted lock digest. Package/freeze/smoke wrappers and every external descendant run later in a separate token-free environment. Existing Gateway, Event Bus, checkpoint record schema, runtime defaults, Web outward contracts, and non-Desktop behavior remain unchanged.

## Technical Context

**Language/Version**: Python 3.12; TypeScript 5.6; React 18; Electron 32; Node.js/npm versions already used by repository CI

**Primary Dependencies**: Existing LoopPlane Host/controller/checkpoint/artifact/capability/model composition; AnyIO and Python standard library (`json`, `sqlite3`, `zipfile`, `hashlib`, `tempfile`, `pathlib`, `os`, `ctypes`); existing Electron/Vite/React/Web presentation dependencies. No new runtime dependency, optional extra, or third-party JavaScript package name. Proposed build-only resolution: `pyinstaller==6.21.0` plus all transitive Windows/Python-3.12 wheels and SHA-256 hashes in `pyinstaller-build-windows-py312.txt`, installed only into a cleared isolated `uv venv`.

**Storage**: Desktop explicitly selects the existing SQLite checkpoint backend and artifact store under an active profile generation; portable safe `profile.json` contains identity, Projects, references, and preferences but no drafts; device-private workspace bindings and `device-private/profile-owner.lock` live outside all generations and portable backups. Before pointer/proof/journal reads, store construction, or Host creation, the process acquires an OS-backed exclusive lock for the canonical profile root; aliases resolve to one lock identity, contention yields public-safe `busy` with zero Host, kernel process death releases ownership, and unsupported/remote/ambiguous locking fails closed. A pristine generation records `checkpoint_state=absent_uninitialized` and `artifact_state=absent_uninitialized`; pre-Host validation proves absence without opening/creating SQLite or ArtifactStore, and first normal Host durable use retains existing store-owner initialization semantics. Fail-closed platform publication produces a canonical immutable Generation Publication Receipt bound into pointer/proof/journals: POSIX uses file/directory/parent `fsync` with the exercised physical-power-loss claim, while Windows uses documented regular-file flush, supported-local-volume write-through move/replace, and reopen with a process/application-crash claim only. After Host open, generation contents are mutable; startup validates receipt lineage and current profile/SQLite/artifact consistency rather than publication-time hashes. Proof-before-Host bootstrap, two complete COW journal slots, ambiguous-proof startup adjudication, one all-writer Profile Mutation Lease, and one `DesktopRuntimeOwner` govern candidate/previous Host handover. Restored `relink_required` state blocks stale binding lookup until explicit relink. Host-owned snapshot facades create/validate consistent portable SQLite plus provenance-eligible referenced-artifact inventories. Existing capability/private configuration store is excluded from portable backup. No new checkpoint record/table/schema.

**Testing**: pytest unit/contract/integration; Ruff; strict mypy; package build; existing architecture/boundary guards; TypeScript typecheck; Vitest for Web/Desktop/shared presentation/main/preload/client; Vite production builds; browser accessibility/reflow regression; backup security/recovery fixtures; isolated PyInstaller/electron-builder artifact smoke.

**Target Platform**: Local Electron desktop app, with Windows 11 as the mandatory real GUI/package smoke platform for 078. Cross-platform process/path/package code remains portable, but evidence is claimed only for platforms actually exercised.

**Project Type**: Multi-language desktop application plus additive Python Host facade and shared Web/Desktop presentation workspace.

**Performance Goals**: Initialization succeeds or reports unavailable/incompatible runtime within 10 seconds; protocol frames/queues/requests/subscriptions are bounded; 100 mixed malformed/stale/duplicate/cross-session cases produce zero unintended run; three-pane flow permits exactly one active interaction without draft/history loss; backup/restore observes declared 4 GiB archive, 8 GiB expanded, 10,000-entry safety limits rather than unbounded allocation.

**Constraints**: No local network listener; Electron main is sole sidecar owner; one OS-backed exclusive Profile Ownership Lock is acquired before profile recovery and prevents a second process from constructing a Host; no raw renderer IPC/RPC/process/filesystem escape hatch; sidecar uses Host public facades only and never reaches through to live SQLite/ArtifactStore internals; runtime events equal existing `serialize_event` output; one generated principal and one inner interaction lease per profile; raw workspace/archive paths are trusted-process-only and never outward; resume `None` remains current `Path.cwd()` semantics; authorized conversation and eligible artifact content remains lossless but cannot cross into secondary status/audit/error/log/manifest metadata; unsent drafts are not persisted or backed up. Fresh bootstrap validates explicit absent-uninitialized checkpoint/artifact state without creating stores and constructs no Host before valid pointer/proof/publication-receipt lineage. Backup holds the all-writer Profile Mutation Lease from Host snapshot/profile serialization through archive finalization; restore holds it from validation reservation through commit/cancel/expiry/shutdown cleanup, rejecting every competing session, interaction, Project, workspace (including persisted `workspace.revalidate`), capability, profile, backup, or restore mutation except owning commit/cancel and bounded teardown that starts no durable work. POSIX publication carries the exercised physical-power-loss claim; Windows carries only documented process/application-crash consistency on supported local filesystems and explicitly excludes parent-directory sudden-power-loss persistence. Active generation contents remain mutable. Proof-effect/acknowledgement ambiguity permits no in-process rollback/cleanup mutation. `relink_required` blocks binding lookup, including identical-ID stale bindings. Restore retains two COW full-preimage journals until proof authority and swaps to a candidate Host or exact journal-recovered previous Host before dispatch resumes. No Event/checkpoint/Gateway/default/Web outward-contract drift; no remote/CLI/distributed/multi-user/release/signing work; no build-lock materialization before external-human Stage A, no product implementation before T005, and no freeze/package/artifact smoke before T090's third delivery review. Every applicable submitted GitHub PR review has API-visible `APPROVED` state, API-controlled review ID/node ID, non-null `submitted_at`, `user.type=User`, OWNER/MEMBER/COLLABORATOR `author_association`, exact immutable expected-approver equality, case-insensitive inequality from the singular PR author's login, and `commit_id` equal to the exact reviewed commit whose complete non-truncated tree determines the canonical review bundle and lock/source digest. Verification requires immutable shared repository/PR/expected-approver inputs plus T002 for bootstrap, T002+T005 for final, and T002+T005+T090 review-ID/expected-commit pairs for delivery; prior locators never come from ADR/evidence/config or list/search APIs. It accepts explicit `LOOPPLANE_STAGE_B_GITHUB_TOKEN` only in an isolated verifier process, never ambient `gh`/git credentials; final/delivery modes refetch all required complete trees and enforce the exact T002-to-T005 full-tree allowlist. Minimum read permissions, bounded version-pinned REST calls, and every credential/HTTP/rate/timeout/API-shape failure are fail closed with no token/header/raw-body logging. After descriptor emission the token is scrubbed, and every package/sidecar wrapper plus `npm` lifecycle/`uv`/PyInstaller/electron-builder descendant runs token-free. T003 is limited to the focused RED verifier/root-lock-routing test; T004 must make the verifier pass before package migration or any later implementation.

**Scale/Scope**: One canonical Desktop profile root with exactly one OS-lock-owning sidecar process, one Desktop window with multiple panes, one active interactive session, at most 64 outstanding RPC requests and 8 subscriptions, durable local sessions/artifacts, one all-writer-excluding portable whole-profile backup/restore transaction at a time, and one first-party shared presentation package. 079 remote parity remains blocked until 078 is Verified.

## Phase 0: Research Output

See [research.md](research.md). Decisions:

- JSON-RPC 2.0 envelopes over bounded strict UTF-8 LF stdio under `loopplane.desktop.stdio` V1; no batch/client notifications/generic methods/local HTTP.
- 5-second initialize/shutdown limits, 1 MiB control and 8 MiB event frames, 64 KiB prompts, bounded queue/concurrency/subscriptions/JSON.
- Electron main sole process/RPC/native chooser owner; strict BrowserWindow settings, sender validation, typed preload facade, wrapped unsubscribe.
- Existing normalized runtime event serialization embedded unchanged.
- Additive `LoopPlaneHost.resume_session` composition and optional controller resume scope preserving current default.
- Default-unavailable Host instance portable snapshot/export and inactive staged-validation facades, plus a public non-instance `loopplane.host.validate_active_generation` startup facade that proves pristine absence or initialized current state with zero Host/normal-store construction and zero filesystem creation/mutation; no sidecar live-store reach-through.
- One generated principal, portable Desktop Projects, Host-owned star state, private device workspace bindings, an outer OS-backed canonical-root Profile Ownership Lock, one inner sidecar interaction lease, multiple read panes, and no persisted/backed-up unsent drafts.
- Narrow `CoworkPresentationHost` with separate Web and Desktop adapters; no HTTP imitation or UI copy.
- Checkpoint-derived logical-turn audit with explicit honesty limits.
- Existing SQLite checkpoint/artifact durability selected only by Desktop; pristine bootstrap validates `absent_uninitialized` stores without creating them, and only checkpoint-referenced provenance-eligible Gateway artifacts are portable.
- Full authorized user/model/tool history and eligible artifacts preserved in an unencrypted allowlisted backup; LoopPlane-owned secrets/config/private mappings and direct/recursive workspace collection excluded; fresh bootstrap is proof-before-Host. Generation publication uses explicit POSIX physical-power-loss versus Windows process/application-crash guarantees and an immutable publication receipt that does not freeze later mutable state. An all-writer Profile Mutation Lease spans backup snapshot/finalization and restore reservation/commit; restore uses two COW full-preimage journals plus matching proof, defers ambiguous proof-effect decisions to startup, and rejects `relink_required` before stale binding lookup; the sole runtime owner swaps to a readiness-checked candidate Host or exact journal-recovered previous Host before dispatch resumes. Backup/restore internal causes map only through the fixed RPC code/category/retryable/recovery/message-key table.
- Hash-constrained Windows/Python-3.12 PyInstaller 6.21.0 graph plus Stage-B-bound `pyproject.toml`/`uv.lock` and exact six-extra runtime graph; commit-derived accepted dependency snapshots close worktree lock replacement; a third delivery-reviewed exact source snapshot closes worktree source replacement; the final-reviewed sole root npm lock/app-lock absence and delivery-reviewed implementation are consumed only in an isolated package-build snapshot; required fully triggered Windows x64 CI uses the sidecar/package wrappers and exact smoke CLI only after Stage C.

## Implementation Strategy

### Wave 1 — Host resumed-interaction seam

Use focused failing tests to add the minimal resumed interactive context manager. Preserve existing `resume()` signatures/behavior except for an optional keyword-only controller scope defaulting to current `Path.cwd()`. Prove principal activation, bind/attach/replay, submit/cancel/answer, teardown on all exits, and zero checkpoint/event/default changes.

### Wave 2 — Sidecar RPC and profile core

Build strict framing plus a pure injected initialize/dispatcher/writer state machine first without modifying the executable bridge or constructing a Host/store/profile. Then implement/export the public active-generation validator and canonical-root ownership/bootstrap gate; only after those tests pass may the launchable raw `{op:"run"}` bridge be replaced and wired behind that gate. Canonicalize the profile root and acquire its OS-backed exclusive Profile Ownership Lock before reading pointer/proof/journals, creating stores, or constructing a Host; a second process returns public-safe `busy` with zero Host, crash ownership is kernel-released, and unsupported/remote/ambiguous locking fails closed. Before sidecar startup can call it, this wave first implements and exports the Host-owned public non-instance `loopplane.host.validate_active_generation` facade under RED Host tests. For a pristine root, publish a receipt declaring checkpoint/artifact `absent_uninitialized`, invoke that now-existing facade to prove their absence without opening/creating SQLite or ArtifactStore, write/reread the receipt-bound bootstrap proof and exact pointer, then let first normal Host durable use retain existing store-owner initialization. Non-pristine startup invokes the same facade's dedicated read-only schema/SQLite ownership/artifact-consistency path before constructing the SQLite-rooted `DesktopRuntimeOwner`; tests inject the Host-owned provider and prove zero Host/normal-store constructors plus zero created or mutated filesystem entries on every result. POSIX tests own file/directory/parent `fsync`; Windows tests own supported-volume/regular-file flush/write-through move/reopen and the narrower process-crash claim. Crash before/after proof/pointer, lock acquisition/release, unsupported volume, and later mutable-generation restart are test-first. Profile work extends this owner with Projects, Host-backed star/session methods, `relink_required`-before-binding-lookup, transient-draft exclusion, the inner interaction lease, and the all-writer Profile Mutation Lease. TDD malformed/version/state/ordering/correlation/idempotency/bounds/crash/public-safety cases before happy-path expansion.

### Wave 3 — Electron main/preload boundary

Implement the sidecar supervisor, byte-oriented decoder, pending request routing, child lifecycle, native folder/file pickers, sender-validated per-operation handlers, frozen preload facade, and idempotent subscriptions. Before handler implementation, Electron main tests own the complete BrowserWindow surface: exact packaged local renderer/preload paths, restrictive bundled-asset CSP, denial of unexpected top-frame navigation, `setWindowOpenHandler` denial for every V1 request, and deny-by-default permission request/check handlers, with a regression proving the ordinary packaged renderer still loads. Test-first ownership covers every named facade operation—not only interaction—including app status/shutdown, session list/history/rename/star/delete/fork, all Project/workspace/native-picker operations, inspection/audit/agent controls/capability actions, and backup/restore; each has bounded schemas, global typing, public-safe error/recovery mapping, and no raw identifier/path/channel escape. Remove the old raw `sidecar:send`/`sidecar:line` channel rather than retaining compatibility escape hatches.

### Wave 4 — Shared presentation and cowork shell

After T004 has created the complete root/app/shared manifest graph and sole root lock and T005 has content-bound its digest plus app-lock absence, use only the accepted package snapshot without adding third-party names or opportunistic upgrades. Move reusable shell/chat/settings/inspection behavior into the first-party presentation package; keep Web and Desktop thin adapters/composition roots. Add multi-pane/read-only/single-active/sidebar/fork/keyboard/focus/error/unavailable behavior and rerun Web regressions continuously.

### Wave 5 — Audit, backup, and restore

Add the checkpoint-derived Host audit facade and default-unavailable instance portable snapshot export/inactive-staged validation provider, reusing the public non-instance active-generation startup validator already delivered in Wave 2; then implement disclosure, Host-owned SQLite/provenance-eligible artifact snapshot, canonical manifest/hashes/limits, streamed no-follow staging, and mutation-reserving archive identity token. Backup acquires the all-writer Profile Mutation Lease before Host snapshot/profile serialization and retains it through archive finalization; restore reserves the same lease through commit/cancel/expiry/shutdown cleanup. While held, every competing session create/rename/star/fork/delete, interactive open/submit/answer, Project/workspace/capability/profile mutation (including persisted `workspace.revalidate`), backup, or restore fails before Host/profile dispatch; only the owning restore transition and bounded cancel/release/shutdown teardown may proceed, and teardown starts no new durable work. Restore reuses the platform-scoped publication primitive and canonical receipt: POSIX proves file/directory/both-parent `fsync` under the physical-power-loss claim; Windows proves supported-local-volume regular-file flush/write-through move/reopen under process/application-crash consistency and documents the power-loss limitation. Pointer publication uses two checksummed COW journal slots containing full previous proof/pointer preimages and receipt, platform durable-write transitions, and a proof only after candidate Host readiness/runtime-owner swap. A definitive pre-proof failure rolls back exactly; possible proof effect without acknowledgement freezes mutations and defers the decision to startup. Current mutable generation restart, identical-ID stale-binding rejection before lookup, post-proof binding cleanup, single-slot faults, both-slot fail-lock, and cleanup interruption are all adversarially tested. Every backup/restore internal cause is translated through the single fixed wire/error/message-key table, never exposed as a new RPC category.

### Wave 6 — Packaging, CI, docs, and board transition

After T003 observes focused RED tests, T004 implements bootstrap/final/delivery verifier modes and materializes all dependency manifests before the sole root lock under the T002 bootstrap authority, with no install/build. T005 then verifies a distinct final submitted review, derives both accepted lock digests and app-lock absence from its commit, accepts ADR 0015, and unlocks T006+. Bootstrap/final/delivery verifier calls require immutable shared repository/PR/expected-approver inputs plus respectively T002, T002+T005, or T002+T005+T090 review-ID/commit pairs and the sole explicit short-lived token environment seam confined to the verifier process. They require the reviewer to differ from the singular PR author, use minimum read permissions and version-pinned singular GitHub REST resources, reject incomplete/truncated authority data, stale/substituted prior locators, and any non-allowlisted T002-to-T005 path/type/mode/blob diff, and emit no accepted descriptor or secret-bearing diagnostics on credential/API failure. Final-mode verifier calls materialize exact commit-derived Python/npm dependency bytes into fresh accepted-input snapshots. After T006–T089 implementation and source gates, T090 obtains the third delivery review and delivery mode independently refetches all three authorities, rederives T005 inputs without trusting records, and materializes exact reviewed product/wrapper/workflow/smoke source. After the verifier emits its bounded descriptor and exits, all GitHub token variables are removed. Token-free `scripts/build-desktop-sidecar.ps1` derives the exact six-extra runtime graph, strict-syncs only accepted snapshot paths into a fresh venv, validates it, and freezes only delivery-reviewed source with no ambient/global/credential route. Token-free `scripts/build-desktop-package.ps1` builds from that reviewed source root, installs the exact T005-reviewed root/app/shared manifest/lock bytes there, calls only the sidecar wrapper for freeze, and runs `npm ci`/lifecycle/build/electron-builder only in that snapshot with explicit child-environment scrubbing. Path-filtered Windows source gates cover the full determinant set, while a separate `pull_request_review`-submitted delivery job takes T090 review ID/commit from the immutable event, T002/T005 locators from maintainer repository variables, and expected approver from `LOOPPLANE_DESKTOP_EXPECTED_APPROVER`; its tokenized step refetches all three authorities and emits the descriptor, while a separate token-free step runs the exact reviewed source through the package wrapper and external-CWD smoke. Linux/apps-only checks are supplemental. Copy the complete built artifact to a fresh out-of-checkout root and run `smoke-desktop-artifact.ps1 ... -Scenario all` there. The PowerShell driver uses only built-in .NET UI Automation. Packaged-smoke mode enables Electron accessibility after readiness and before BrowserWindow creation, then the driver preflights exactly one instance of each frozen Name/ControlType pair on ordinary visible Group/Button/Edit/List controls; it never assumes DOM-to-AutomationId mapping or falls back to localized text. It submits `loopplane packaged smoke`, waits for `loopplane-packaged-smoke-ok`, closes/relaunches via normal window automation, observes persisted history, and checks bounded failure diagnostics. Packaged-only smoke mode uses the external scratch profile and existing `ScriptedModel`; it exposes no generic automation or runtime control channel. Synchronize `docs/desktop-gui.md`, `docs/manual-qa.md`, other required docs, and `[Unreleased]`, but do not version/release. Update board only after fresh evidence and external-human completion approval.

## Rollback and Default Preservation

- Each wave is an independently reviewable/revertible boundary and does not rely on later waves to restore old runtime semantics.
- Omitted resume scope retains existing `Path.cwd()` behavior; Desktop-only SQLite selection leaves global StorageConfig defaults unchanged.
- Removing Desktop launch/use leaves Host, CLI, Web, Gateway, Event Bus, checkpoint records, dependencies, and defaults equivalent to pre-078 behavior.
- Protocol/profile/backup incompatibility fails closed; no mixed-major fallback or mutation replay after crash.
- The OS-backed Profile Ownership Lock is acquired before recovery and remains process-held until bounded shutdown; contention, unsupported locking, or ambiguous canonical identity yields zero Host, while process death relies on kernel release rather than PID/text staleness guesses. Fresh bootstrap publishes/reopens an initial generation whose checkpoint/artifact states are `absent_uninitialized`, proves absence without creating either store, writes/rereads its receipt-bound proof before the exact pointer, and constructs no Host until pointer/proof/receipt lineage match. Backup and restore hold the all-writer Profile Mutation Lease for their complete normative windows; `restore.validate` never changes the active pointer. POSIX uses the exercised physical-power-loss publication protocol; Windows uses documented supported-local-volume process/application-crash publication and explicitly does not claim parent-directory sudden-power-loss persistence. The receipt binds the publication event, not later mutable contents. Restore commit rereads two full-preimage journal slots, swaps to a candidate Host, and publishes the matching proof. A definitive pre-proof failure rolls back exactly; possible proof effect without acknowledgement freezes all recovery/binding mutations and startup alone decides. `relink_required` blocks identical-ID stale bindings until explicit relink and post-proof cleanup. No matching proof or unambiguous journal authority means zero-Host fail-lock.
- If shared workspace clean-install proof fails, Web remains on its current composition and the extraction is not accepted.
- If package smoke fails, source tests do not justify board completion; existing demo development shell remains the rollback surface until a complete package is proven.
- `.superpowers/**`, build outputs, profiles/backups/logs/tokens/PIDs, QA artifacts, and unrelated user changes remain excluded.

## Post-Design Constitution Check

The pre-research PASS statuses remain valid. Phase 1 fixes ownership and compatibility: main owns process/IPC, sidecar uses Host-only runtime/storage seams, normalized events/checkpoints/Gateway/Web contracts remain unchanged, bindings stay private and `relink_required` blocks stale lookup, authorized sensitive content is separated from secondary public-safe surfaces, drafts remain transient, and backup uses Host-owned snapshots. Fresh bootstrap is proof-before-pointer/Host. Publication guarantees are explicit rather than overstated: POSIX owns the exercised physical-power-loss claim; Windows owns documented process/application-crash consistency and a Stage-B-accepted power-loss limitation. The immutable publication receipt does not freeze active mutable state; ambiguous proof effect is startup-adjudicated with no in-process recovery mutation; redundant journals and exact authority prevent generation guessing. Shared UI remains first-party/transport-neutral and all behavior Desktop-local/default-preserving. No constitution violation or complexity waiver is requested.

Implementation is nevertheless **blocked**. Stage A must first authorize the exact PyInstaller lock materialization. T002 then needs a submitted bootstrap review binding design/Python authorities/candidate lock and authorizing only T003/T004 while ADR 0015 remains Proposed. T003 observes RED; T004 implements the verifier and complete dependency-manifest/root-lock materialization without install/build. T005 then needs a distinct final submitted review whose immutable commit derives the final tree/bundle, both lock digests, exact runtime extras, verifier/tests, and app-lock absence; only it may accept ADR 0015 and unlock T006+. Any missing/dismissed review, missing/insufficient explicit credential or permission, HTTP/rate/timeout/redirect/API-shape/truncated-tree failure, actor/commit/review-ID/bound-artifact/Python-authority/lock drift, or need for a new declared dependency, Event/checkpoint/Gateway/default/Web outward-contract change invalidates the applicable gate; no ambient auth fallback or secret-bearing evidence is allowed.

## Complexity Tracking

No constitution violation is accepted. The new private process protocol, Host-owned portable snapshot boundary, profile-generation/journaled restore boundary, Desktop Project metadata, and first-party presentation workspace are justified product boundaries documented by ADR 0015 rather than exceptions to architecture. After convergence analysis and a fresh independent GO audit, the only permitted unresolved item is authorization: source implementation waits for the explicit human gate.
