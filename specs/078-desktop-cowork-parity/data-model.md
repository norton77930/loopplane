# Data Model: Desktop Cowork Parity

## Scope and ownership

This model describes 078's Desktop-private state and public-safe projections. It does not replace or extend runtime events, checkpoint records, Gateway objects, or Web outward models.

| Owner | Durable data | Transient data |
|---|---|---|
| Runtime controller/checkpoint store | Local sessions, history, model/context metadata, existing checkpoint records | Reconstructed controller sessions |
| LoopPlane Host | Existing public session/history/capability/cost/agent-control projections plus additive portable snapshot/validation and turn-audit facades | Bound sink/reviewer/session handle and Host-owned snapshot operation |
| Desktop sidecar profile | Portable profile metadata, fixed principal, Desktop Projects, opaque workspace references, safe preferences | Interaction/profile-mutation/restore-transaction leases, RPC sessions, subscriptions |
| Desktop device-private store | Workspace reference to canonical path bindings | Current path validation result |
| Electron main | None beyond OS/browser-window preferences explicitly allowed by profile contract | Sidecar process, RPC pending map, renderer subscriptions, native picker handles |
| Renderer | No authoritative durable runtime/profile data | Pane layout, view drafts, focus, selected inspection tab, presentation cache |

## Desktop Profile

Represents one local operator's durable Desktop identity and safe application state.

| Field | Type | Rules |
|---|---|---|
| `schema_version` | integer | Positive; exact supported version required before mutation. |
| `profile_id` | opaque UUID string | Generated by the trusted sidecar; never chosen by renderer. |
| `principal_id` | opaque UUID string | Generated once with the profile; immutable through normal operation; preserved by backup/restore. |
| `created_at` | UTC timestamp | Trusted-side generation time. |
| `updated_at` | UTC timestamp | Changes only after atomic durable mutation. |
| `projects` | ordered list of Desktop Project | Safe grouping metadata only; no path or runtime ownership. |
| `workspace_references` | ordered list of Workspace Reference | Contains no canonical or absolute path. |
| `preferences` | Desktop Preferences | Safe allowlisted values only; unsent pane drafts are excluded. |
| `backup_format_max` | integer | Highest backup format the profile implementation can restore; diagnostic only. |

### Invariants

- Exactly one principal belongs to one profile.
- The renderer cannot create, replace, or submit `principal_id`.
- Profile data contains no provider credential/token, raw private capability configuration, absolute workspace path, unsent pane draft, PID, log, or active-run state.
- Durable mutation is serialized by the Profile Mutation Lease.

## Profile Generation

A directory that is quiescent only while it is validated and published, then becomes the mutable active root for portable profile state plus runtime-owned checkpoints and artifacts. Publication lineage is immutable; current generation contents are not.

| Field/path | Ownership | Backup status |
|---|---|---|
| `profile.json` | Desktop profile store | Included after canonicalization. |
| `checkpoints.sqlite3` | Existing SQLite checkpoint store | May be absent only for a receipt-declared zero-session `absent_uninitialized` bootstrap; otherwise included only through the Host-owned portable snapshot facade using SQLite backup semantics. Sidecar bootstrap never creates/opens it. |
| `<session>/artifacts/**` | Existing artifact store | May be absent only for the same pristine bootstrap; otherwise only checkpoint-referenced, provenance-eligible Gateway artifact files copied by the Host-owned snapshot facade after regular-file/no-follow/root/identity checks are included. |
| `capabilities/**` | Existing capability store | Excluded in V1 because it may contain private endpoints/configuration and can be re-established safely. |
| transient/staging/log/cache/PID files | Process-specific | Always excluded. |

Device-private Workspace Bindings are not members of any Profile Generation. They live under the profile-root `device-private/` sibling owned by the current device, are never selected by the active-generation pointer, and cannot be revived by generation publication or rollback.

### State transitions

`staging -> validated -> durably-published -> proved-active -> retained-for-rollback -> garbage-collectable`

- A generation is never active before all schema/integrity checks pass.
- Initial and restore generations become `durably-published` only after the platform-scoped publication protocol succeeds: POSIX uses regular-file and bottom-up directory `fsync`, same-filesystem rename, and both parent-directory `fsync`s with a physical-power-loss claim; Windows uses documented regular-file `FlushFileBuffers`, a supported-local-volume same-volume write-through move/replace, and post-move reopen with only a process/application-crash consistency claim. Unsupported/error outcomes fail before pointer mutation, and Stage B must accept the Windows physical-power-loss limitation.
- Publication creates a canonical immutable Generation Publication Receipt object/digest recording the publication event, generation ID, platform/durability scope, sequence/nonce, and publication-time validation result. It does not permanently hash the generation's later mutable checkpoints, artifacts, or profile state.
- Fresh bootstrap writes/rereads a receipt-bound `bootstrap` proof, then the exact pointer, and constructs no Host until pointer/proof/receipt lineage and current generation validation match. The receipt declares `checkpoint_state=absent_uninitialized` and `artifact_state=absent_uninitialized` only when profile/session inventories are empty; pre-Host validation proves absence without opening/creating either store. The first normal Host durable operation may create them through existing owners. A pristine crash between proof and pointer may complete only the proof-embedded pointer; any other bootstrap mismatch fails locked.
- The active-generation pointer selects a live mutable generation only when an Active Generation Proof matches its exact bytes/digest, generation ID, and canonical publication receipt; startup then either proves the exact pristine absent-uninitialized state or validates current profile schema, SQLite integrity/ownership, and artifact consistency without comparing mutable files to publication-time hashes.
- Before pointer replacement, both copy-on-write Restore Journal slots durably contain the full exact previous pointer and previous-proof preimages plus old/new generation IDs.
- Pointer replacement is the publication boundary; a restore is committed only after successful candidate Host readiness/runtime-owner swap and publication of a matching Active Generation Proof.
- Startup encountering an unproved candidate uses either valid full-preimage journal slot to restore the exact previous proof/pointer pair before Host construction. If no unambiguous valid slot exists, it fails locked and constructs no Host.
- Generation switch or rollback never copies, restores, or re-selects device-private Workspace Bindings; restored references remain `relink_required` until an explicit current-device bind.
- The previous active generation is retained until the new generation, its freshly composed Host, and the matching active proof are verified or explicit safe cleanup occurs.

|---|---|---|

| `theme` | enum | Known safe theme values only. |
| `pane_order` | list of opaque pane IDs | References Pane Preference entries; no session payload. |

## Desktop Project

Safe profile-owned grouping for sessions and an optional Workspace Reference.

| Field | Type | Rules |
|---|---|---|
| `project_id` | opaque UUID string | Generated by trusted sidecar; immutable. |
| `label` | bounded string | Safe display label; no path derivation or private configuration. |
| `workspace_id` | opaque Workspace Reference ID or null | Optional grouping/default selection only; current Workspace Binding validation still governs interaction. |
| `session_ids` | ordered unique list of opaque session IDs | Every member must belong to the profile principal; one session belongs to at most one project in V1. |
| `created_at` / `updated_at` | UTC timestamps | Trusted-side metadata. |

Rules:

- Creating, renaming, removing, or assigning a project changes only Desktop profile metadata.
- Removing a project makes its sessions ungrouped and never deletes sessions, checkpoints, artifacts, Workspace References/Bindings, or workspace contents.
- Project membership is portable and included in backup; a referenced workspace still becomes `relink_required` after restore.
- Projects own no runtime policy, principal, path, capability configuration, or interaction lease.

## Workspace Reference

Public-safe identity for a user-selected workspace.

| Field | Type | Rules |
|---|---|---|
| `workspace_id` | opaque UUID string | Generated by trusted sidecar; immutable across safe relink. |
| `label` | bounded string | Derived or user-renamed safe label; never an absolute/canonical path. |
| `availability` | enum | `available`, `relink_required`, `unavailable`, or `validation_failed`. |
| `allowed_actions` | set of enum | Derived by trusted owner; e.g. `open`, `relink`, `remove`. |
| `created_at` | UTC timestamp | Trusted-side time. |
| `updated_at` | UTC timestamp | Changes after reference metadata mutation or a persisted availability revalidation result. |

### Relationships

- A Desktop Profile owns zero or more Workspace References.
- A Local Session may refer to at most one `workspace_id` through existing safe workspace context/projection.
- A Workspace Reference has zero or one device-private Workspace Binding on the current machine, but `availability="relink_required"` is a hard pre-lookup denial: the owner must not consult or reuse an old binding even when the restored `profile_id` and `workspace_id` are identical.

### State transitions

- `relink_required -> available` after native selection, canonical validation, and atomic binding update.
- `available -> unavailable` after a Profile-Mutation-Lease-gated current revalidation persists failure.
- `available/unavailable -> relink_required` after restore or explicit unlink.
- Removal deletes the private binding and safe reference only after sessions' read-only history remains addressable; it never deletes workspace contents.

## Workspace Binding (device-private)

Trusted mapping that authorizes a local working scope. It is not portable and is never projected to renderer or protocol callers.

| Field | Type | Rules |
|---|---|---|
| `workspace_id` | opaque UUID string | Must belong to current profile. |
| `canonical_path` | absolute canonical path | Written only by trusted sidecar after a main-owned native picker result. |
| `identity_fingerprint` | platform-appropriate safe internal identity | Used only to detect moved/replaced targets; never projected. |
| `validated_at` | UTC timestamp | Must be refreshed before interactive create/resume. |
| `validation_state` | internal enum | `valid`, `missing`, `changed`, `unauthorized`, `unsafe_link`, `error`. |

### Validation rules

- No renderer-typed arbitrary path is accepted.
- The target must exist, be a directory, satisfy existing workspace/tool scope policy, and pass canonical/link validation.
- A failed or cancelled relink does not overwrite a binding that belongs to the currently active non-restored reference state.
- Restore never reconstructs this entity; restored references start `relink_required`. Binding resolution checks that state before any device-private lookup, so an identical-ID pre-restore binding is ignored. It may remain quarantinable until candidate proof authority so rollback can still serve the previous generation, then is removed/quarantined; only explicit successful relink creates the candidate's usable binding.

## Profile Ownership Lock

Generation-external OS-backed ownership of one canonical Desktop profile root across processes. The lock target lives at `device-private/profile-owner.lock`, but file contents, PID text, timestamps, and stale-file presence are never authority.

| Field | Type | Rules |
|---|---|---|
| `canonical_profile_root` | trusted canonical local path | Main/sidecar-owned; never renderer-visible or portable; aliases must resolve to the same lock identity. |
| `lock_handle` | process-held OS handle | Supported POSIX exclusive advisory lock or Windows exclusive handle/byte-range lock; held before recovery reads, store creation, or Host construction. |
| `state` | enum | `acquiring`, `owned`, `releasing`, `released`, `unsupported`. |
| `owner_diagnostic` | bounded private metadata | Optional PID/start metadata for private diagnostics only; never used to steal/break a live lock or returned to renderer. |

- Non-blocking acquisition failure returns public-safe `busy` and creates zero `DesktopRuntimeOwner`/Host.
- Unsupported, remote, or ambiguous lock semantics fail closed before profile mutation.
- Normal shutdown releases after dispatch stops and Host teardown; kernel process termination releases ownership after crash.
- A later process may recover/open the profile only after it acquires the same OS lock; it never trusts or deletes a stale lock file as proof of ownership.
- This lock is excluded from backup/restore and remains outside generation publication.

## Desktop Interaction Lease

Profile-wide transient ownership of the sole interactive session inside the one process holding the Profile Ownership Lock; therefore no second process can create a competing lease for the same canonical profile root.

| Field | Type | Rules |
|---|---|---|
| `lease_id` | opaque trusted-side ID | Never persisted or accepted from renderer. |
| `session_id` | opaque session ID | Must belong to profile principal. |
| `pane_id` | safe renderer pane correlation | Diagnostic/UX correlation only; not an authorization identity. |
| `operation` | enum | `create`, `resume`, `submit`, `approval`, `question`, `cancel`. |
| `acquired_at` | monotonic/UTC metadata | Used for diagnostics only. |
| `state` | enum | `acquiring`, `active`, `releasing`, `released`. |

### State transitions

`none -> acquiring -> active -> releasing -> none`

- Any acquisition failure returns to `none`.
- A second acquisition while active is rejected before Host/model invocation.
- Terminal outcome, cancel completion, Host context exit, sidecar shutdown, stdin EOF, and connection failure all release ownership.
- Backup creation and restore validation/commit require no active interaction; restore/profile mutation cannot coexist with this lease.

## Profile Mutation Lease

Transient exclusive writer gate for every operation that can change the active generation or generation-external profile state. The outer Profile Ownership Lock prevents another process from bypassing it.

| Field | Type | Rules |
|---|---|---|
| `mutation_id` | opaque trusted-side ID | Process-local and main/sidecar generated. |
| `kind` | enum | `session`, `interaction`, `project`, `workspace`, `capability`, `backup`, `restore`, `profile_update`. |
| `state` | enum | `acquiring`, `active`, `reserved`, `releasing`, `released`. |
| `owner_operation` | exact allowlisted operation/token | Determines the sole continuation allowed while reserved; never renderer authority. |

Restore validation atomically acquires the exclusive Profile Mutation Lease and a Restore Transaction reservation after confirming no active Desktop Interaction Lease. The reservation remains active through commit, cancel, expiry, connection shutdown, or sidecar restart cleanup. Backup likewise requires no active interaction and holds the lease from before Host snapshot/profile serialization through archive finalization. While backup/restore owns or reserves the lease, every competing session rename/star/fork/delete/create, interactive submit/answer/open, Project/workspace mutation—including persisted `workspace.revalidate` availability/validation metadata—capability action, backup, or restore request fails `busy` before Host/profile dispatch. Only the owning restore commit/cancel and bounded shutdown/cancel/release teardown may pass; teardown cannot start new durable work. The Host-owned snapshot facade supplies the checkpoint/artifact export inside the same lease interval as profile/project/preference serialization, and the UI must not claim success before finalization.

## Desktop Runtime Owner

Sidecar-owned transient holder of the one live `LoopPlaneHost` and the factory/config needed to compose a Host for an exact Profile Generation.

| Field | Type | Rules |
|---|---|---|
| `active_generation` | opaque generation ID | Must equal the recovered/published pointer used to construct the current Host. |
| `host` | `LoopPlaneHost` handle | The only Host used by RPC methods; never renderer-visible. |
| `state` | enum | `ready`, `quiescing`, `candidate_open`, `swapping`, `recovering`, `failed`. |

Restore handover rules:

1. The Profile Mutation Lease prevents any new interaction or Host-backed profile request during publication/handover.
2. After candidate pointer publication, compose and readiness-check a fresh Host rooted at the candidate generation; the existing Host remains quiescent and must not receive further requests.
3. Only after candidate readiness succeeds may the owner close the old Host and atomically install the candidate Host. Only after that swap may recovery publish an Active Generation Proof matching the exact candidate pointer; a later journal `verified` state is cleanup/audit evidence, not the positive activation authority.
4. If candidate construction/readiness, old-Host close, owner swap, or proof publication fails and it is definitively established that proof replacement did not take effect and left the proof target unchanged, close the candidate, use a valid redundant journal slot to restore the exact prior proof/pointer pair, and retain or freshly reconstruct a Host rooted at the previous generation before releasing the reservation.
5. If proof replace, flush, or reopen may have taken effect but its durable effect or acknowledgement/reread is uncertain, perform no recovery-driven Host close, rollback, cleanup, binding deletion, or further pointer/proof/journal mutation. Stop dispatch, retain both journals, enter the public-safe restart-required fail-locked state, and let startup alone adjudicate a matching proof versus exact journal rollback.
6. A process crash before a matching candidate proof is handled at next startup by journal rollback before any Host construction; startup then constructs exactly one Host from the recovered and independently proved pointer. Missing/ambiguous proof plus no valid journal fails locked.
7. After commit success, every subsequent session/history/artifact/profile operation uses only the candidate Host. The old Host and previous-generation stores are never reused for new writes.

## RPC Connection

| Field | Type | Rules |
|---|---|---|
| `connection_state` | enum | `starting`, `initializing`, `ready`, `draining`, `closed`, `failed`. |
| `protocol` | protocol ID + major/minor | Set only by successful handshake. |
| `runtime_event_schema` | integer | Must equal supported existing schema. |
| `capabilities` | safe negotiated set | Exact named methods/notifications and availability; no wildcard. |

| `subscriptions` | map of subscription ID to Runtime Subscription | Bounded at 8. |
| `notification_sequence` | monotonic integer | Connection-level gap/duplicate detection. |

### State transitions

- `starting -> initializing` after child spawn and stdio readiness.
- `initializing -> ready` only after compatible `initialize` response.
- `ready -> draining` after shutdown begins; new non-shutdown requests are rejected.
- Any malformed/oversized frame, protocol mismatch, child error/exit, or unexpected EOF moves to `failed` and rejects all pending requests with one public-safe category.
- `draining -> closed` after graceful response/EOF or forced kill fallback.

### Portable Artifact

| Field | Type | Rules |
|---|---|---|
| `relative_path` | safe snapshot-relative path | Host-generated; no live source path. |
| `session_id` / `reference` / `call_id` | opaque existing identifiers | Must match the checkpoint reference and ArtifactStore metadata. |

## Active Generation Proof

Small independently durable profile-root record that binds the only pointer/generation startup may open normally. It is outside every generation and uses the accepted platform-scoped durable-replace primitive: supported POSIX local filesystems use same-directory temp write, regular-file `fsync`, atomic same-filesystem replace, and parent-directory `fsync` within the exercised physical-power-loss scope; supported Windows local volumes use regular-file `FlushFileBuffers`, same-volume write-through replace/move, and post-move reopen validation for process/application-crash consistency, without claiming directory-handle flush or parent-directory sudden-power-loss persistence.

| Field | Type | Rules |
|---|---|---|
| `proof_version` | integer | Exact supported recovery-proof format. |
| `proof_sequence` | non-negative integer | Monotonically increases for each committed active generation. |
| `proof_kind` | enum | `bootstrap` for initial profile publication or `restore` for a committed restore. |
| `restore_id` | opaque ID or null | Required for `restore`; null for bootstrap. |
| `active_generation` | opaque generation ID | Must equal the generation named by the exact pointer bytes. |
| `generation_publication_receipt` / `generation_receipt_sha256` | canonical object + digest | Binds the proof to the immutable publication event, generation ID, platform/durability scope, sequence/nonce, and publication-time validation result. It is not a hash contract for later mutable generation contents. |
| `active_pointer_bytes_b64` / `active_pointer_sha256` | exact proved pointer representation | Reread pointer bytes must match exactly before Host construction. |
| `verified_at` | UTC timestamp | Diagnostic only; never used to order/recover. |
| `record_sha256` | digest | SHA-256 over canonical JSON excluding this field. |

A bootstrap proof is written/reread before its exact pointer on a pristine profile, and no initial Host is constructed until pointer, proof, canonical publication receipt, and current-generation validation match. A restore proof is written only after candidate Host readiness, old-Host close, and atomic candidate installation in `DesktopRuntimeOwner`. A reread-valid matching proof is commit authority; later journal `verified`/cleanup interruption is resumable and does not roll back the proved candidate. If proof replacement/flush may have taken effect but reread/acknowledgement is uncertain, the current process performs no rollback or recovery-file/binding mutation, retains both journals, stops dispatch, and requires startup to reread proof/pointer/receipt and choose candidate commit or exact journal rollback. Journal state alone never proves candidate activation. A pointer without a matching proof requires exact journal rollback or fail-locked startup.

## Restore Journal Slot

Two redundant profile-root files, `restore-journal-a.json` and `restore-journal-b.json`, each independently contain the complete recovery preimage. Both are durable and reread-valid in `prepared` state before candidate-pointer publication. A state transition copy-on-write replaces only the older/inactive slot and preserves the other complete valid slot until a matching Active Generation Proof is independently durable.

| Field | Type | Rules |
|---|---|---|
| `journal_version` | integer | Exact supported recovery format. |
| `slot` | enum | `a` or `b`; must match the containing filename. |
| `journal_sequence` | non-negative integer | Monotonic within one restore lineage; timestamps never decide precedence. |
| `restore_id` | opaque ID | Matches the reserved Restore Transaction. |
| `archive_sha256` | digest | Correlates source validation. |
| `state` | enum | `prepared`, `published`, or `verified`. |
| `previous_generation` / `candidate_generation` | opaque generation IDs | Both must exist in the profile generation namespace as required by state. |
| `previous_pointer_bytes_b64` / `previous_pointer_sha256` | exact prior pointer representation | Used to restore byte-identical active-pointer bytes. |
| `previous_proof_bytes_b64` / `previous_proof_sha256` | exact prior proof representation | Restores the independently proved prior active state. |
| `candidate_pointer_bytes_b64` / `candidate_pointer_sha256` | exact candidate pointer representation | Used to identify an unproved publication without guessing from directories. |
| `candidate_generation_publication_receipt` / `candidate_generation_receipt_sha256` | canonical object + digest | Binds journal recovery to the immutable candidate publication event and accepted platform durability scope before pointer replacement; it does not freeze later active-generation contents. |
| `candidate_proof_sha256` | digest or null | Set only by a `verified` transition after the independent proof is durable. |
| `updated_at` | UTC timestamp | Diagnostic only; recovery decision is sequence/checksum/content-based. |
| `record_sha256` | digest | SHA-256 over canonical JSON excluding this field. |

Slots are accepted together only when checksum-valid records have the same restore lineage and identical recovery preimages. The initial `prepared` pair may share a sequence when state/recovery fields match and only slot/checksum differ; the first transition replaces slot A, then later transitions replace the lower-sequence slot. A single torn, truncated, corrupt, or missing slot is ignored when the other is valid. Conflicting lineages, any other equal-sequence disagreement, or two invalid/unavailable slots before a matching candidate proof fail locked. Journal cleanup happens one slot at a time with directory durability only after exact rollback has restored a matching previous proof/pointer pair or a matching candidate proof is independently durable.

## Restore Transaction

| Field | Type | Rules |
|---|---|---|
| `restore_id` | opaque trusted-side ID | Sidecar-generated; the in-memory token is process-local but durable journal correlation survives crash recovery. |
| `archive_source` | main-selected absolute path held only by trusted sidecar state | Passed over trusted main-to-sidecar RPC; renderer never receives it and it is never logged, persisted in profile/checkpoints/events, or backed up. |
| `archive_sha256` | digest | Binds validation/commit and durable journal to exact source bytes. |
| `source_version` | backup version | Parsed during validation. |
| `staging_generation` | opaque generation ID | Created on same volume as active pointer. |
| `candidate_generation_publication_receipt` | canonical object/digest or null | Set only after the platform-scoped publication protocol and publication-time validation succeed; records POSIX physical-power-loss scope or Windows process/application-crash scope explicitly. |
| `previous_generation` | opaque generation ID | Retained until commit verification succeeds. |
| `previous_pointer_bytes` | exact bytes/digest | Persisted in both Restore Journal slots before publication so startup can restore the byte-identical pointer. |
| `previous_proof_bytes` | exact bytes/digest | Persisted in both slots so rollback restores the prior pointer's independent activation proof. |
| `candidate_pointer_bytes` | exact bytes/digest | Persisted in both slots and later bound by the candidate Active Generation Proof. |
| `state` | enum | `selected`, `validating`, `reserved`, `staged`, `prepared`, `published`, `proved`, `verified`, `committed`, `rolled_back`, `failed`, `expired`, `cancelled`. |
| `failure_category` | public-safe enum or null | No raw archive name/path/error echo when unsafe. |

### State transitions

- `selected -> validating -> reserved -> staged -> prepared -> published -> proved -> verified -> committed`
- `validating` atomically reserves the Profile Mutation Lease; commit/cancel/expiry/shutdown is the only release path.
- Before `published`, both fsync'd Restore Journal slots contain `restore_id`, exact previous pointer/proof bytes and digests, exact candidate pointer bytes/digest, previous/candidate generation IDs, archive hash, and `prepared` state.
- Any failure before pointer replacement: `... -> failed/cancelled/expired`, delete/quarantine staging, keep the active pointer/proof pair unchanged, remove/close the reservation.
- After pointer replacement, copy-on-write one slot to `published`; after candidate normal open and runtime-owner swap succeed, publish and reread the matching Active Generation Proof (`proved`), then copy-on-write a slot to `verified`, finalize `committed`, and clear slots one at a time. If proof effect is possible but acknowledgement is uncertain, transition only to a fail-locked restart-required condition outside this state machine; do not write another state or rollback in-process.
- Startup with a matching candidate proof completes commit/cleanup even if a surviving slot is older. Without that proof, either valid slot restores the exact previous proof/pointer pair and moves to `rolled_back`; no valid unambiguous slot means fail locked with no Host. Startup also validates current mutable generation consistency rather than publication-time file hashes.
- Active interaction or any competing writer rejects before `validating`; while `reserved`, session create/rename/star/fork/delete, interactive open/submit/answer, Project/workspace/capability/profile mutation, competing backup, and competing restore remain blocked before Host/profile dispatch. Only the owning restore commit/cancel and bounded no-new-durable-work teardown may proceed.
