# Contract: Desktop stdio RPC V1

**Status**: Proposed — source implementation is blocked until the 078 human gate accepts this contract and ADR 0015.

**Scope**: Private local protocol between Electron main and the bundled Python sidecar. It is not a Web API, renderer API, remote-control protocol, or runtime event schema.

## 1. Roles and trust

- **Client**: Electron main only. It owns child process and stdio, generates request/mutation IDs, enforces renderer operation allowlists, and never exposes protocol envelopes to the renderer.
- **Server**: One bundled Python sidecar process. It dispatches exact named methods and integrates runtime work only through `LoopPlaneHost` public facades.
- **Renderer**: Not a protocol peer. It cannot supply method names, request IDs, principal IDs, absolute paths, raw JSON, or process-control values.
- No local network listener is opened.

## 2. Wire format

- JSON-RPC envelope version: exact string `"2.0"`.
- Product protocol: `loopplane.desktop.stdio`, version `{major: 1, minor: 0}`.
- Encoding: strict UTF-8 without BOM.
- Framing: exactly one JSON object followed by LF (`0x0A`). CRLF is accepted only by removing one terminal CR before decode completion; emitted frames use LF.
- Top-level arrays/batches, scalar JSON, empty lines after initialization, client notifications, duplicate object keys, non-finite numbers, and unpaired surrogate content are rejected.
- The receiver counts frame bytes before decode/parse.
- Electron main uses a byte-oriented scanner and `StringDecoder`; split UTF-8 sequences must not be decoded per chunk.
- The sidecar uses one serialized stdout writer. Diagnostic stderr never contains request payloads, paths, credentials, or raw internal exceptions.

## 3. Bounds

| Limit | V1 value | Failure |
|---|---:|---|
| Initialization deadline | 5 s | Terminate child; public `incompatible_or_unavailable_runtime` state |
| Graceful shutdown deadline | 5 s | Force terminate child after pending request rejection |
| Control frame | 1 MiB | Connection failure; no partial dispatch |
| `runtime.event` frame | 8 MiB | Subscription/connection failure; event is not truncated |
| Prompt UTF-8 bytes | 64 KiB | Method error before Host submission |
| Ordinary title/reason/label | 4 KiB | Validation error |
| JSON nesting depth | 32 | Parse/validation error |
| Object keys | 128 per object | Parse/validation error |
| Pending requests | 64 | `busy` without dispatch |
| Active subscriptions | 8 | `busy` without Host attach |
| Notification queue | 128 frames or 16 MiB | Fail affected interaction and close safely |
| Manifest entries | Defined by backup contract | Reject before restore publication |

Changing a limit requires a protocol-minor update when backward-compatible or protocol-major update when acceptance semantics change.

## 4. Envelope shapes

### Request

```json
{"jsonrpc":"2.0","id":"m-00000001","method":"session.list","params":{}}
```

- `id` is a non-empty opaque Electron-main-generated string, maximum 128 UTF-8 bytes.
- IDs are unique for the sidecar process lifetime.
- Mutation requests also contain `mutation_id`, generated by Electron main, maximum 128 bytes.
- Unknown top-level fields are rejected.

### Success response

```json
{"jsonrpc":"2.0","id":"m-00000001","result":{"sessions":[]}}
```

### Error response

```json
{
  "jsonrpc":"2.0",
  "id":"m-00000001",
  "error":{
    "code":-32005,
    "message":"The operation is not available in the current state.",
    "data":{"category":"invalid_state","retryable":false,"recovery":"close_active_interaction"}
  }
}
```

Error `data` is an allowlisted public-safe object. It never echoes request input, method parameters, principal IDs, absolute paths, credentials/tokens, private rules/configuration, provider payloads, raw exceptions, tracebacks, PIDs, or stderr.

### Server notification

```json
{
  "jsonrpc":"2.0",
  "method":"runtime.event",
  "params":{
    "notification_seq":17,
    "subscription_id":"sub-opaque",
    "session_id":"session-opaque",
    "run_id":"run-opaque-or-null",
    "event":{}
  }
}
```

`notification_seq` starts at 1 after successful initialization and increments by one for every server notification on the connection. A gap, duplicate, or regression causes Electron main to fail the affected projection rather than guess ordering.

## 5. Initialization

`initialize` is the first and only allowed pre-ready request.

### Request

```json
{
  "jsonrpc":"2.0",
  "id":"m-00000000",
  "method":"initialize",
  "params":{
    "protocol":{"name":"loopplane.desktop.stdio","major":1,"minor":0},
    "runtime_event_schema":1,
    "client":{"name":"loopplane-desktop-main","version":"<app-version>"},
    "requested_capabilities":["sessions","interaction","projects","inspection","workspace","backup"]
  }
}
```

### Success result

```json
{
  "protocol":{"name":"loopplane.desktop.stdio","major":1,"minor":0},
  "runtime_event_schema":1,
  "server":{"name":"loopplane-desktop-sidecar","version":"<package-version>"},
  "methods":[
    "initialize","system.status","system.shutdown",
    "session.list","session.history","session.rename","session.setStarred","session.delete","session.fork",
    "session.createInteractive","session.resumeInteractive","session.releaseInteractive",
    "interaction.submit","interaction.cancel","interaction.answerApproval","interaction.answerQuestion",
    "project.list","project.create","project.rename","project.remove","project.assignSession",
    "inspection.get","agentControls.get","capabilities.list","capabilities.invokeAction","audit.list",
    "workspace.list","workspace.bind","workspace.relink","workspace.remove","workspace.revalidate",
    "backup.describe","backup.create","restore.validate","restore.commit","restore.cancel"
  ],
  "notifications":["runtime.event","runtime.outcome","runtime.state","runtime.subscriptionClosed"],
  "capabilities":{
    "sessions":"available",
    "interaction":"available",
    "projects":"available",
    "inspection":"available",
    "workspace":"available",
    "backup":"available"
  },
  "limits":{
    "control_frame_bytes":1048576,
    "runtime_event_frame_bytes":8388608,
    "prompt_bytes":65536,
    "pending_requests":64,
    "subscriptions":8
  }
}
```

Rules:

- Protocol name and major must match exactly.
- The client's minor must be less than or equal to the server's supported minor; the server returns the selected minor.
- Runtime-event schema must match exactly. No translation is performed.
- Methods and notifications are exhaustive exact arrays for the selected minor, never wildcard capabilities or abbreviated examples.
- `sessions=available` requires all six non-interactive `session.*` methods; `interaction=available` requires the three interactive-session methods plus all four `interaction.*` methods; `projects=available` requires all five `project.*` methods; `inspection=available` requires `inspection.get`, `agentControls.get`, `capabilities.list`, `capabilities.invokeAction`, and `audit.list`; `workspace=available` requires all five `workspace.*` methods; `backup=available` requires `backup.describe`, `backup.create`, `restore.validate`, `restore.commit`, and `restore.cancel`. If any required method is absent, that capability is `unavailable` rather than partially available.
- `initialize`, `system.status`, and `system.shutdown` are lifecycle methods and are not implied by a feature capability.
- Before `initialize` can report any feature capability `available`, the sidecar must hold the OS-backed exclusive Profile Ownership Lock for the canonical profile root and complete pointer/proof/receipt recovery; lock contention returns `-32004 busy`, exposes no owner/PID/path, and constructs zero Host.
- No other request is dispatched before successful initialization.
- Repeated `initialize` is an invalid state.
- Initialization failure does not mutate profile data; kernel-released crash ownership may be acquired only by a later process that reruns full recovery.

## 6. Method allowlist

Every method rejects unknown fields and validates opaque identifiers against the active profile principal. `mutation_id` is required for methods marked **M**. A duplicate request ID returns the cached terminal response for that process lifetime and never repeats a side effect; an ID reused with a different method or canonical params fails the connection. Electron main never retries an unacknowledged mutation after sidecar failure.

Before dispatch, every method marked **M** passes through the single Profile Mutation Lease writer gate. While backup owns the lease or restore owns/reserves it, competing session create/rename/star/fork/delete, interactive open/submit/answer, Project/workspace mutation (including persisted `workspace.revalidate`), capability action, backup, or restore fails `-32004 busy` before any Host/profile call. Only the reservation-owning `restore.commit`/`restore.cancel` and bounded `system.shutdown`, interaction cancel, or release teardown may pass; teardown cannot begin new durable work. The outer OS-backed Profile Ownership Lock prevents another sidecar process from bypassing this in-process gate.

### Lifecycle

| Method | Mutates | Purpose |
|---|---|---|
| `initialize` | No | Negotiate protocol and capabilities. |
| `system.status` | No | Return public-safe readiness/profile/lease status. |
| `system.shutdown` | Yes (M) | Stop accepting work, release waits/subscriptions/leases, flush durable stores, and exit. |

### Sessions and interaction

| Method | Mutates | Required core parameters | Result summary |
|---|---|---|---|
| `session.list` | No | filters with bounded search text and paging | Safe principal-owned session summaries. |
| `session.history` | No | `session_id`, bounded page/cursor | Existing public-safe history projection. |
| `session.rename` | Yes (M) | `session_id`, `title`, `mutation_id` | Updated safe summary. |
| `session.setStarred` | Yes (M) | `session_id`, boolean `starred`, `mutation_id` | Updated Host-owned starred summary. |
| `session.delete` | Yes (M) | `session_id`, explicit confirmation token, `mutation_id` | Deleted marker; never project/workspace contents. |
| `session.fork` | Yes (M) | `session_id`, exact source sequence/point, confirmation token, `mutation_id` | New independent session summary. |
| `session.createInteractive` | Yes (M) | optional `workspace_id`, safe model/control drafts, `pane_id`, `mutation_id` | `session_id`, `subscription_id`, accepted host projections. |
| `session.resumeInteractive` | Yes (M) | `session_id`, optional `workspace_id`, `pane_id`, `mutation_id` | `subscription_id`, replay boundary, accepted projections. |
| `session.releaseInteractive` | Yes (M) | `subscription_id`, `mutation_id` | Released state after safe context teardown. |
| `interaction.submit` | Yes (M) | `subscription_id`, `prompt`, optional output schema and one-run permission draft, `mutation_id` | Accepted run correlation; terminal result arrives by notification and/or response per implementation contract test. |
| `interaction.cancel` | Yes (M) | `subscription_id`, `mutation_id` | Cancellation requested/settled state. |
| `interaction.answerApproval` | Yes (M) | `subscription_id`, exact pending approval ID, allowed decision, `mutation_id` | Accepted/rejected pending-request state. |
| `interaction.answerQuestion` | Yes (M) | `subscription_id`, exact pending question ID, bounded answer, `mutation_id` | Accepted/rejected pending-request state. |

Session mutation rules:

- `session.setStarred` calls the existing Host-owned persisted-star facade; the renderer never mutates a local-only duplicate.
- Session search is a bounded query over principal-owned safe summaries/history and never exposes cross-principal existence.
- Project membership is managed by the separate profile-owned methods below; deleting a session removes only stale project membership after Host deletion succeeds.

### Desktop Projects

| Method | Mutates | Purpose |
|---|---|---|
| `project.list` | No | Return safe profile-owned project summaries and principal-owned session membership. |
| `project.create` | Yes (M) | Create an opaque project with bounded label and optional Workspace Reference. |
| `project.rename` | Yes (M) | Rename profile metadata only. |
| `project.remove` | Yes (M) | Remove grouping only; sessions/workspaces/bindings/contents remain. |
| `project.assignSession` | Yes (M) | Assign/unassign one principal-owned session; one project maximum in V1. |

Project methods use the Profile Mutation Lease, never accept paths/principals, and do not alter checkpoints/runtime state except removing stale membership after a separately successful Host session deletion.

Interaction rules:

- `session.createInteractive` and `session.resumeInteractive` acquire the profile-wide Desktop Interaction Lease before opening a Host `Session` context.
- Only the lease-owning subscription may submit/cancel/answer.
- A second interactive open fails before Host/model invocation and names only a safe pane/session correlation suitable for UX.
- `session.resumeInteractive` uses a freshly validated Workspace Binding. No binding means read-only history plus `workspace_relink_required`.
- `interaction.submit` is invalid while another run is active on the same subscription or a pending approval/question is awaiting an answer incompatible with submit.
- Unknown/completed approval/question IDs have no effect.
- Terminal outcome does not destroy history; release may occur automatically after the operation according to the accepted lifecycle tests, but lease ownership must never survive context teardown.

### Inspection and host-owned controls

| Method | Mutates | Purpose |
|---|---|---|
| `inspection.get` | No | Return available public-safe context, cost, budget, upload/artifact, and session inspection projections. |
| `agentControls.get` | No | Return Host-owned active/settled agent-control projection. |
| `capabilities.list` | No | Return safe capability status/actions without private config. |
| `capabilities.invokeAction` | Yes (M) | Invoke one exact Host-supported capability action; no generic tool/MCP dispatch. |
| `audit.list` | No | Return checkpoint-derived metadata-safe Turn Audit Entries. |

Unknown/unpriced/unavailable values remain explicit and are never coerced to zero, allowed, active, or configured.

### Workspaces

Absolute paths are trusted main-to-sidecar parameters only. They are never returned, logged, placed in errors, runtime events, checkpoints, Web projections, backups, or renderer IPC payloads.

| Method | Mutates | Purpose |
|---|---|---|
| `workspace.list` | No | Return safe Workspace Reference projections. |
| `workspace.bind` | Yes (M) | Canonicalize/validate a main-selected directory path and atomically create a reference/binding. |
| `workspace.relink` | Yes (M) | Validate a new main-selected path and atomically replace a binding while preserving the opaque reference where safe. |
| `workspace.remove` | Yes (M) | Remove reference/binding metadata only; never delete filesystem contents. |
| `workspace.revalidate` | Yes (M) | Revalidate the private binding and atomically persist safe availability plus validation timestamps before interactive use. |

Cancelled or failed native selection does not call a workspace mutation method. Validation failure returns only a safe category/recovery action.

### Backup and restore

Absolute archive source/destination paths are trusted main-to-sidecar parameters only and follow the same non-disclosure rule.

| Method | Mutates | Purpose |
|---|---|---|
| `backup.describe` | No | Return disclosure text, inclusion/exclusion summary, and supported format. |
| `backup.create` | Yes (M) | After explicit disclosure acknowledgement and native destination selection, create/finalize one allowlisted archive. |
| `restore.validate` | Yes (M) | Acquire/reserve the Profile Mutation Lease, validate a native-selected archive into bounded staging, and return a short-lived opaque `restore_token` plus safe summary. |
| `restore.commit` | Yes (M) | Revalidate token/source and the same live reservation, require explicit confirmation, durably publish/reopen the candidate generation and receipt before pointer mutation, publish with redundant full-preimage COW journals, prove the post-swap candidate pointer/receipt independently, and retain rollback point. |
| `restore.cancel` | Yes (M) | Delete/quarantine the token's staging data, release the reservation, and leave the active pointer/generation unchanged. |

Restore tokens are sidecar-generated, connection/profile scoped, short-lived, and do not encode source paths. `restore.validate` is an idempotent side-effecting staging mutation: it atomically reserves the sole Profile Mutation Lease after proving no active interaction. The reservation blocks new interactions and all other profile mutations until `restore.commit`, `restore.cancel`, expiry, connection shutdown, or sidecar restart cleanup. A token is invalidated by any failed source/hash recheck or attempted conflicting mutation. Validation alone never replaces current data.

## 7. Notifications

| Notification | Payload rule |
|---|---|
| `runtime.event` | `event` is exactly `json.loads(serialize_event(runtime_event))`; wrapper adds only correlation/sequence fields. Event content may include authorized conversation/tool payloads and must route only to the conversation projection, never secondary status/audit/error/log/manifest metadata. |
| `runtime.state` | Desktop control state such as interaction opened, waiting, cancelling, or draining; no new RuntimeEvent meaning. |
| `runtime.outcome` | Public-safe terminal RunOutcome projection correlated to subscription/session/run. |
| `runtime.subscriptionClosed` | Final reason category and whether history remains readable; emitted at most once per subscription. |

Ordering:

1. Notifications use the single connection `notification_seq`.
2. Runtime events preserve their existing internal order/sequence.
3. `runtime.outcome` follows all runtime events accepted for that run.
4. `runtime.subscriptionClosed` is last for the subscription.
5. Unknown or completed subscriptions are ignored by renderer adapters and reported as protocol diagnostics without cross-session mutation.

## 8. Error taxonomy

| JSON-RPC code | Category | Meaning |
|---:|---|---|
| `-32700` | `parse_error` | Invalid UTF-8/JSON/duplicate keys/depth. |
| `-32600` | `invalid_request` | Invalid envelope or fields. |
| `-32601` | `method_not_found` | Method outside negotiated allowlist. |
| `-32602` | `invalid_params` | Bounded schema validation failure. |
| `-32603` | `internal_failure` | Contained unexpected failure; no raw detail. |
| `-32001` | `incompatible_protocol` | Product/runtime-event schema mismatch or unsupported portable-backup format/profile-schema compatibility; the fixed method-specific `messageKey` distinguishes initialization from backup validation without changing `error.data.category`. |
| `-32002` | `not_found` | Principal-owned resource absent; enumeration-safe. |
| `-32003` | `conflict` | Mutation/request/lease conflict. |
| `-32004` | `busy` | Capacity or profile-wide interaction/mutation lease unavailable. |
| `-32005` | `invalid_state` | Operation not valid in current lifecycle state. |
| `-32006` | `workspace_relink_required` | No currently validated workspace scope. |
| `-32007` | `unsafe_input` | Archive/workspace input rejected without echo. |
| `-32008` | `unavailable` | Capability/model/bundled component unavailable. |
| `-32009` | `cancelled` | Operation safely cancelled. |
| `-32010` | `deadline_exceeded` | Bounded operation deadline passed. |
| `-32011` | `durability_unsupported` | Required platform-scoped publication guarantee is unavailable (POSIX file/directory fsync scope or Windows supported-local-volume file-flush/write-through/reopen scope); no pointer mutation occurred. |
| `-32012` | `publication_failed` | Generation or recovery-record durable publication failed and was contained before activation or exact rollback. |

`durability_unsupported` uses `contact_support`; `publication_failed` uses `retry` only when the exact prior authority remains usable, otherwise the connection transitions to a bounded failed state with `restart_runtime`. Backup/restore cause labels such as `unsafe_archive`, `integrity_failed`, `profile_busy`, or `rolled_back` are internal selections only and MUST use the single cause-to-wire/message-key table in the Desktop IPC contract; they are never additional RPC categories. `error.data.recovery`, when present, uses exactly one shared enum value: `retry`, `restart_runtime`, `relink_workspace`, `wait`, `close_active_interaction`, or `contact_support`. Electron main performs an exhaustive one-to-one mapping to the preload `DesktopError.recovery` field; combined or unknown values are protocol errors, not strings for the main process to reinterpret. Unknown internal exceptions map to `internal_failure`. For backup/restore cause translation, the sole unknown fallback is `-32603 internal_failure`, `retryable=true`, `recovery=restart_runtime`, and `messageKey=desktop.error.internal_failure` as fixed by the Desktop IPC table. They may be correlated in private test instrumentation but not by renderer-visible raw values.

## 9. Failure and shutdown semantics

- Malformed/oversized input is never partially dispatched.
- Child `error`, child `exit`, unexpected stdout EOF, writer failure, notification overflow, or protocol ordering violation rejects all pending Electron-main promises with one bounded public-safe state.
- Pending approval/question waits are released through existing Host/Session teardown.
- Main first invokes `system.shutdown`, stops accepting renderer mutations, waits up to 5 seconds, then kills the child if needed.
- No mutation is automatically replayed after child failure. Read-only projections may be refreshed after an explicit new initialization.
- Startup incompatibility does not modify active authority. Fresh bootstrap publishes/reopens the initial generation and canonical publication receipt, writes/rereads its receipt-bound proof before its exact pointer, and constructs no Host until pointer/proof/receipt lineage plus current-generation validation match. Restore validation never changes active authority. Candidate publication uses the accepted platform scope: POSIX file/directory/both-parent `fsync` under the exercised physical-power-loss claim, or Windows supported-local-volume regular-file flush/write-through move/reopen under process/application-crash consistency with no parent-directory sudden-power-loss claim. The immutable receipt is bound into journals/pointer/proof but does not freeze later mutable generation contents. Two full-preimage COW slots plus post-swap proof govern recovery; possible proof effect without acknowledgement freezes in-process mutation and startup alone decides proof-versus-rollback. Restored `relink_required` state blocks any stale identical-ID binding lookup until explicit relink.

## 10. Compatibility

- V1 minor additions may add optional result fields or new separately negotiated methods/notifications; existing meanings and required fields cannot change.
- Unknown result fields may be ignored only after a compatible minor is selected and only where the schema marks them optional.
- Major mismatch fails closed. There is no mixed-version fallback.
- `runtime_event_schema` compatibility is exact.
- This protocol never changes `/v1`, generated Web contracts, Event Bus schema, checkpoint record schema, Gateway SPI/stage, or runtime defaults.
